## P3-1 — Отсутствующие поля ошибочно считаются корректным rate state

**Где:** `lib/transcript-stats.js`, определение пригодности previous record
перед chronological guard в `writeJsonAtomic()`.

Предыдущий validator принимал отсутствующие slots как null, а пустой slot
object — как пригодный из-за отсутствующего used. Тип resetsAt не проверялся.
Поэтому запись с одним capturedAt, с `fiveHour: {}` либо
`fiveHour: { resetsAt: {} }` могла блокировать восстановление из корректного
наблюдения, если её timestamp был немного больше.

**Воспроизведение:** такой cache получает capturedAt=now+1000, то есть остаётся
в пределах допустимого skew. Затем передаётся корректный fiveHour.used=25
с capturedAt=now. До исправления кэш не обновлялся, и reader не возвращал 25.
Все три варианта воспроизведены native filesystem fixtures.

**Исправление:** выделен `validRateState()` для этого выбора.
У record должен присутствовать хотя бы один известный rate-slot.
Ненулевой slot обязан иметь хотя бы одно известное поле used/resetsAt,
с допустимыми типами. Явный null и корректные partial slots остаются допустимыми.

**Проверка закрытия:** шесть тестов в `test/rate-cache-empty-record.test.js`:

- три malformed records больше не блокируют repair;
- более новые null, used-only и resetsAt-only записи сохраняются побайтово.

Существующие snapshot CAS, chronological guard и проверки будущего timestamp
не ослаблены. Тесты предыдущего раунда на interleave и repair также проходят.

Приоритет P3: речь о восстановлении некорректного advisory cache, а не о
сохранности settings.json или отказе основного installer.

## P3-2 — Один snapshot выполняет два одинаковых SHA-256

**Где:** `lib/fs-atomic-identity.js:captureRegularFileSnapshot`.

Digest вычислялся отдельно для верхнего contentDigest и для
expectedDestination.contentDigest, хотя использовался один уже прочитанный
Buffer. Это лишняя работа на каждом присутствующем файле, включая пустой.

**Исправление:** digest вычисляется один раз после проверки стабильности
snapshot и переиспользуется в обоих представлениях.
Формат результата, обработка отсутствующего файла и алгоритм не менялись.

**Проверка закрытия:** `test/snapshot-digest.test.js` проверяет отсутствие,
пустой и непустой файл. Результаты сравниваются с native SHA-256; отдельно
считаются вызовы createHash. Для отсутствия их ноль, для присутствующего
содержимого один вместо прежних двух.

Использованы маленькие fixtures, не нагрузочный benchmark.
Сокращение числа вызовов подтверждено; конкретное ускорение всего installer
по wall-clock этим тестом не заявляется.
