## P2-1 — Обычная публикация кэша не сохраняет более свежего writer

**Где:** `lib/transcript-stats.js:writeJsonAtomic`,
вызовы из `persistRateLimitsCache`.

Миграция уже передавала полный snapshot, но обычное сохранение rate/context-cache
использовало безусловный atomic writer. A мог подготовить старую запись,
B — полностью опубликовать новую, после чего A заменял B.
Отдельно запоздавшее наблюдение могло перезаписать запись с большим capturedAt,
уже существующую к началу вызова.

**Воспроизведение:** на границе native open собственного temp A синхронно
выполняется настоящий `persistRateLimitsCache()` для B, затем A продолжается.
До исправления после записей 300 000 и 400 000 чтение возвращало старые
300 000. Проверены context-only и совместное обновление global/context;
также воспроизведён последовательный приход более старого наблюдения.

**Исправление:**

- Каждый leaf публикуется с полным expectedDestination, захваченным до записи.
  Если другой writer успел изменить destination, его содержимое сохраняется.
- Уже существующее пригодное наблюдение с большим capturedAt не заменяется
  более старым. Проверка будущей даты использует актуальный wall-clock
  с существующим допуском skew, поэтому ошибочная будущая запись не блокирует repair.
- Некорректные context/rate значения не получают приоритет только из-за timestamp.
- Нерегулярный destination отклоняется до нового snapshot-read.
  Сбой global cache по-прежнему не блокирует независимую запись session context.

Это отдельные условные публикации, не новая общая multi-file transaction.
Fail-silent поведение при конфликте сохранено.

**Проверка закрытия:** семь тестов в `test/rate-cache-publication.test.js`:
два interleave-сценария, старое наблюдение на входе, poisoned future cache,
malformed newer cache, независимость session write при сбое global leaf
и запрет чтения нерегулярного context leaf.
Три исходных сценария потери свежей записи падали до изменения.
Проверены возвращаемые contextWindowSize и rate values, а также сохранность
конфликтующего directory entry. Те же тесты прошли на установленном runtime.

Приоритет P2: затрагивалась актуальность восстановимого advisory cache,
не подтверждённая потеря пользовательского settings.json.

## P2-2 — Optional fingerprint-поля трактуются несогласованно

**Где:** `lib/fs-atomic.js:removeOwnedRegularFile`, построение effectiveExpected.

Нормализованное ожидание допускает независимые optional contentDigest и
contentBytes. Но при отсутствующем digest функция заменяла оба поля текущими
значениями. Явно заданная неправильная длина таким образом терялась:
8-байтовый файл удалялся при ожидании contentBytes=99.

Обратный случай тоже был неверным: при корректном digest и отсутствующей длине
длина оставалась null, и корректное удаление отклонялось. Для atomic publication
эти ограничения уже проверялись независимо.

**Исправление:** observed snapshot дополняет только отсутствующие поля.
Явные digest и contentBytes сохраняются и проверяются; переданные ограничения
не переопределяются. Полный snapshot и legacy identity-only остаются рабочими.

**Проверка закрытия:** пять тестов в `test/removal-fingerprint.test.js`:
identity-only, digest-only, length-only, неправильная length-only,
правильный digest с неправильной длиной. До изменения digest-only ошибочно
отказывал, а wrong-length ошибочно удалял файл.
После исправления отрицательные случаи сохраняют точные bytes на canonical path,
без ненужной quarantine; положительные действительно удаляют leaf.
Все пять прошли и на установленном runtime.

Приоритет P2: дефект подтверждён на API частичных ожиданий; не установлено,
что обычный CLI сейчас передаёт противоречивую length-only комбинацию.

## P3-1 — Contributor guide требует пустой stdout от всех companion-bin

**Где:** `CONTRIBUTING.md`, инструкция по добавлению companion bin, пункт 6.

Совет завершаться с exit 0 и пустым stdout на error path распространялся
одновременно на hooks и statusLine. Это расходилось с контрактом существующих
`cah-status` и probe: они сохраняют непустой fallback/placeholder.

**Исправление:** отдельно описаны silent Stop/PostToolUse hooks и statusLine,
которому нужен non-empty fallback. Diagnostic probe сохраняет placeholder.
Поведение существующих bin ради этой правки не менялось.

**Проверка закрытия:** `test/companion-guidance.test.js` закрепляет различие
в contributor guide. До правки новый contract test падал.
Приоритет P3: исправляется инструкция для будущих изменений, не обнаруженный
дефект нынешнего statusLine output.
